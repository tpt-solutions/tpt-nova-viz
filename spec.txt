Design Spec 05 — tpt-nova-viz
Project: tpt-nova-viz
Role: Visualization-specific runtime extensions for tpt-nova
Layer: Layer 5 (Domain Extension)
License: MIT
Dependency policy: No Apache-only dependencies
Status: Draft v0.1
Primary target: Linux-first, cross-platform by construction
1. Summary
tpt-nova-viz is the visualization domain extension for tpt-nova.
While tpt-nova-games prioritizes real-time interactivity and tpt-nova-sim prioritizes determinism and sensor fidelity, tpt-nova-viz prioritizes precision, scale, and professional-grade data representation.
It transforms tpt-nova into a high-performance visualization platform for engineering, architecture, scientific research, and industrial data analysis. This is where your work on tpt-cad and large-scale data rendering converges with the core engine.
What It Provides
Massive point cloud rendering (billions of points, LOD streaming).
CAD/BIM file parsing and interactive visualization (STEP, IFC, OBJ, glTF).
Precision measurement tools (distance, angle, area, volume).
Annotation and markup systems (3D text, arrows, callouts).
Volumetric data rendering (CT scans, fluid simulations, scientific datasets).
High-accuracy camera controls (orbit, pan, zoom with sub-millimeter precision).
Export to industry-standard formats (PDF, PNG, MP4, glTF).
What It Does NOT Provide
Real-time gameplay or player input (that's tpt-nova-games).
Sensor simulation or AI training (that's tpt-nova-sim).
The core rendering backend (that's tpt-nova core).
The build pipeline (that's tpt-vectis).
2. Naming Rule
Every crate in the tpt-nova-viz workspace must start with:
tpt-nova-viz-
Except the root facade crate:
tpt-nova-viz
Valid examples:
tpt-nova-viz
tpt-nova-viz-pointcloud
tpt-nova-viz-cad
tpt-nova-viz-measure
tpt-nova-viz-annotate
tpt-nova-viz-volume
tpt-nova-viz-camera
tpt-nova-viz-export
Invalid examples:
nova-viz-pointcloud
viz-measure
tpt-visualization
3. Architectural Position
tpt-vectis (toolchain)
  ↓ builds visualization assets/drivers for
tpt-nova (core runtime)
  ↓ extended by
tpt-nova-viz (THIS REPO)
  ↓ used by
  CAD viewers, BIM platforms, scientific visualization tools, industrial inspection systems
Dependency Direction
tpt-nova-viz DEPENDS ON:
  - tpt-nova (core ECS, scheduler, rendering abstraction)
  - tpt-math (vectors, matrices, transforms, precision math)
  - tpt-media (image codecs for export)

tpt-nova-viz DOES NOT DEPEND ON:
  - tpt-nova-games (sibling domain)
  - tpt-nova-sim (sibling domain)
  - tpt-vectis (build-time only)
  - tpt-kinetix (physics not required for pure visualization)

4. Core Subsystems
4.1. tpt-nova-viz-pointcloud
Massive point cloud rendering with LOD streaming.
Components
pub struct PointCloud {
    pub source: PointCloudSource,
    pub total_points: u64,
    pub bounds: Aabb,
    pub color_mode: ColorMode,
    pub point_size: f32,
    pub loaded_chunks: HashSet<ChunkId>,
}

pub enum PointCloudSource {
    File { path: PathBuf, format: PointCloudFormat },
    Stream { uri: String },
    Generated { generator: Box<dyn PointGenerator> },
}

pub enum PointCloudFormat {
    Las,
    Laz,
    Pts,
    Xyz,
    E57,
}

pub struct PointChunk {
    pub id: ChunkId,
    pub bounds: Aabb,
    pub point_count: u32,
    pub lod_level: u8,
    pub gpu_buffer: Option<GpuBufferId>,
}

pub enum ColorMode {
    Uniform(Color),
    ByHeight { min: Color, max: Color },
    ByIntensity,
    ByClassification,
    ByRgb,
}

Systems
pointcloud_stream_system — asynchronously loads chunks based on camera distance and frustum.
pointcloud_lod_system — selects appropriate LOD level per chunk based on screen-space error.
pointcloud_render_system — batches and renders visible chunks with instanced point sprites.
pointcloud_cleanup_system — unloads distant chunks to manage GPU memory.
Drivers
pointcloud_loader_driver — hot-swappable file format parser (LAS, LAZ, E57, custom).
pointcloud_lod_driver — hot-swappable LOD selection algorithm (quadtree, octree, k-d tree).
pointcloud_render_driver — hot-swappable rendering technique (point sprites, splatting, raycasting).
Features
Out-of-core rendering (datasets larger than RAM).
Multi-resolution LOD with seamless transitions.
Frustum culling and occlusion culling.
GPU memory budget management.
Color mapping by elevation, intensity, classification, or RGB.
Point size attenuation based on distance.

5. Integration with tpt-nova-drivers
The visualization domain leverages dynamic drivers for format flexibility and rendering experimentation.
Example: Hot-Swapping a Point Cloud Loader
// Default: Slow but memory-efficient streaming loader
pub struct StreamingPointcloudDriver;
impl Driver for StreamingPointcloudDriver { /* ... */ }

// Upgraded: Fast bulk loader for datasets that fit in RAM
pub struct BulkPointcloudDriver;
impl Driver for BulkPointcloudDriver { /* ... */ }

// At runtime, switch based on dataset size:
if dataset_size < RAM_BUDGET {
    world.swap_driver::<PointCloud>(BulkPointcloudDriver);
} else {
    world.swap_driver::<PointCloud>(StreamingPointcloudDriver);
}

Example: Self-Debugging a Measurement
If a measurement tool reports incorrect distances, tpt-nova-drivers + tpt-eve can:
Detect the anomaly (distance doesn't match expected value).
Analyze the calculation driver.
Generate a corrected driver (e.g., fixing unit conversion bug).
Hot-swap it immediately.

7. Strict Dependency Policy
License: MIT only
Allowed: MIT, BSD-2-Clause, BSD-3-Clause, ISC, Zlib, BSL-1.0
Banned: Apache-2.0 (unless dual-licensed with MIT), GPL-, AGPL-, LGPL-, MPL-, SSPL
Specific Crate Choices
Point cloud formats (LAS/LAZ): las-rs (MIT) or custom parser.
CAD formats (STEP/IGES): Custom lightweight parser or step-parser (if MIT-licensed).
Image codecs (PNG/JPEG): image crate (MIT) or tpt-media.
PDF export: printpdf (MIT) or custom vector renderer.
Video encoding: ffmpeg bindings are GPL, so we must use a pure Rust MIT-licensed encoder or shell out to ffmpeg as an external tool (not a dependency).
DICOM parsing: dicom crate (MIT/Apache-2.0, use MIT) or custom parser.
Critical: Avoid the Apache-2.0 trap in scientific data libraries. Many data format parsers are Apache-2.0 only. For v0.1, we will implement custom parsers for critical formats or explicitly audit for MIT compatibility.

9. Success Criteria
tpt-nova-viz is successful when:
A 10-billion-point LiDAR dataset can be loaded and navigated at 30+ FPS on a mid-range GPU.
A STEP file can be parsed and rendered with correct materials and hierarchy.
A distance measurement between two points on a CAD model is accurate to 0.01mm.
A 3D annotation can be placed, edited, and exported to JSON.
A DICOM CT scan can be rendered with interactive transfer function adjustment.
The camera can orbit, pan, and zoom with sub-millimeter precision.
A high-resolution PNG export completes without blocking the UI.
The entire crate dependency tree passes the strict no-Apache-only cargo-deny check.
10. Non-Goals for v0.1
Photorealistic rendering (that's a core tpt-nova rendering concern; viz focuses on accuracy, not beauty).
Real-time collaboration (multi-user editing is a future feature).
Full STEP/IGES B-rep tessellation (v0.1 focuses on mesh-based CAD like OBJ/glTF; B-rep support is v0.2).
Native mobile support (v0.1 targets desktop Linux/Windows/macOS).
Integration with proprietary CAD kernels (Parasolid, ACIS).
11. Example Use Cases
Use Case 1: LiDAR Inspection
A civil engineer loads a 50-billion-point terrestrial LiDAR scan of a bridge. They:
Navigate the point cloud at 60 FPS using the orbit camera.
Measure crack widths with sub-millimeter precision.
Annotate defects with 3D callouts.
Export annotated views to PDF for the inspection report.
Use Case 2: BIM Coordination
An architect loads an IFC model of a building. They:
Isolate the HVAC system to check for clashes.
Measure clearance distances between ducts and beams.
Annotate coordination issues.
Export a 3D PDF to share with the structural engineer.
Use Case 3: Medical Imaging
A radiologist loads a DICOM CT scan. They:
Adjust the transfer function to highlight bone vs. soft tissue.
Take orthogonal slices (axial, coronal, sagittal).
Measure tumor volume.
Export a video flythrough for the surgical team.
